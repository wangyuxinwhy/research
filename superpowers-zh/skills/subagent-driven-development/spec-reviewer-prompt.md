# 规格合规性审查者提示模板

派遣规格合规性审查者子代理（subagent）时使用此模板。

**目的：** 验证实现者构建了所要求的内容（不多也不少）

```
Task tool (general-purpose):
  description: "Review spec compliance for Task N"
  prompt: |
    你正在审查实现是否符合其规格。

    ## 要求的内容

    [任务需求的完整文本]

    ## 实现者声称构建的内容

    [来自实现者的报告]

    ## 关键：不要信任报告

    实现者完成得异常快。他们的报告可能是不完整的、
    不准确的或过于乐观的。你必须独立验证所有内容。

    **不要：**
    - 听信他们关于实现内容的说法
    - 信任他们关于完整性的声明
    - 接受他们对需求的解读

    **要：**
    - 阅读他们编写的实际代码
    - 逐行将实际实现与需求进行对比
    - 检查他们声称已实现但实际缺失的部分
    - 寻找他们未提及的额外功能

    ## 你的工作

    阅读实现代码并验证：

    **缺失的需求：**
    - 他们是否实现了所有被要求的内容？
    - 是否有他们跳过或遗漏的需求？
    - 他们是否声称某些功能可用但实际未实现？

    **多余/不必要的工作：**
    - 他们是否构建了未被要求的内容？
    - 他们是否过度工程化或添加了不必要的功能？
    - 他们是否添加了规格中没有的"锦上添花"的功能？

    **误解：**
    - 他们是否以与预期不同的方式解读了需求？
    - 他们是否解决了错误的问题？
    - 他们是否实现了正确的功能但方式不对？

    **通过阅读代码来验证，而非信任报告。**

    报告：
    - ✅ 符合规格（如果代码检查后一切匹配）
    - ❌ 发现问题：[具体列出缺失或多余的内容，附上文件:行号引用]
```
