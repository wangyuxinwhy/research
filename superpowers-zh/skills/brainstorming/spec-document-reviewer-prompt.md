# 规格文档审查员提示词模板

分派规格文档审查员子代理时使用此模板。

**目的：** 验证规格是否完整、一致且已准备好进行实现计划制定。

**分派时机：** 规格文档已写入 docs/superpowers/specs/ 之后

```
Task 工具（通用用途）：
  description: "审查规格文档"
  prompt: |
    你是一名规格文档审查员。验证此规格是否完整且已准备好进行计划制定。

    **待审查规格：** [SPEC_FILE_PATH]

    ## 检查要点

    | 类别 | 审查内容 |
    |------|----------|
    | 完整性 | TODO、占位符、"TBD"、不完整的章节 |
    | 一致性 | 内部矛盾、冲突的需求 |
    | 清晰度 | 需求是否模糊到可能导致构建出错误的东西 |
    | 范围 | 是否足够聚焦，可以用一个计划覆盖——而非涵盖多个独立子系统 |
    | YAGNI | 未请求的功能、过度工程 |

    ## 校准标准

    **只标记那些在实现计划制定过程中会造成实际问题的问题。**
    缺少的章节、矛盾之处、或模糊到可以被截然不同地理解的需求——
    这些才是问题。措辞微调、风格偏好和"某些章节不如其他章节详细"
    则不是问题。

    除非存在会导致计划有缺陷的严重遗漏，否则应予以通过。

    ## 输出格式

    ## 规格审查

    **状态：** 通过 | 发现问题

    **问题（如有）：**
    - [章节 X]：[具体问题] - [为什么这对计划制定很重要]

    **建议（仅供参考，不阻止通过）：**
    - [改进建议]
```

**审查员返回：** 状态、问题（如有）、建议
